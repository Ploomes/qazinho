# Idioma

A interface fala **inglês e português**. O i18next guarda as strings; nada em `src/` escreve de
forma fixa uma frase que o usuário lê.

```
src/languages/
├── index.ts          ← a instância do i18next, iniciada uma vez
├── locales/en.ts     ← a fonte da verdade: toda chave nasce aqui
├── locales/pt.ts     ← tipado como `typeof en`, então uma chave faltando não compila
├── library/          ← resolveLanguage, e o teste dele
└── types/Language.ts
```

## As regras

- **O `en.ts` é a fonte da verdade.** Acrescente a chave lá primeiro; o `pt.ts` é tipado contra
  ele, então uma tradução faltando é um erro de tipo, não uma surpresa em runtime.
- **As chaves são `NAMESPACE.KEY`, as duas em SCREAMING_SNAKE**, e o namespace espelha o módulo:
  `CHAT.EMPTY_TITLE`, `RUN.HISTORY`, `SETTINGS.AGENTS_NOTE`. O `COMMON` guarda o que toda tela
  repete.
- **O `t()` é apresentação.** Uma view pode chamar `useTranslation()`, do mesmo jeito que pode
  importar a folha de estilo dela. Um view model também pode, quando monta uma frase a partir do
  estado.
- **Interpole, nunca concatene.** `t('RUN.SUMMARY', { cases, steps })`, nunca
  `` `${cases} cases` ``. A ordem das palavras não é a mesma nos dois idiomas.
- **Uma tabela de constantes guarda a chave, não a frase**: `labelKey: 'STATUS.PASSED'`. É por
  isso que `STATUS` e `CHAT.suggestions` levam chaves.
- O QA escolhe o idioma em Configurações → Aparência. O `useLanguage` o troca no lugar: a janela
  nunca recarrega.
- Os nomes de teste, o código e as mensagens de commit ficam em inglês; o JSDoc, os comentários e
  os `.md`, em português do Brasil. Só o texto que o usuário lê é traduzido entre os dois idiomas.
