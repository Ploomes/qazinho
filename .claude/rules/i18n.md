# Language

The interface speaks **English and Portuguese**. i18next holds the strings; nothing in `src/`
hardcodes a sentence the user reads.

```
src/languages/
├── index.ts          ← the i18next instance, started once
├── locales/en.ts     ← the source of truth: every key lives here first
├── locales/pt.ts     ← typed `typeof en`, so a missing key does not compile
├── library/          ← resolveLanguage, and its test
└── types/Language.ts
```

## The rules

- **`en.ts` is the source of truth.** Add the key there first; `pt.ts` is typed against it, so a
  missing translation is a type error, not a runtime surprise.
- **Keys are `NAMESPACE.KEY`, both SCREAMING_SNAKE**, and the namespace mirrors the module:
  `CHAT.EMPTY_TITLE`, `RUN.HISTORY`, `SETTINGS.AGENTS_NOTE`. `COMMON` holds what every screen
  repeats.
- **`t()` is presentation.** A view may call `useTranslation()`, the same way it may import its
  stylesheet. A view model may too, when it builds a sentence out of state.
- **Interpolate, never concatenate.** `t('RUN.SUMMARY', { cases, steps })`, never
  `` `${cases} cases` ``. Word order is not the same in both languages.
- **A constant table holds the key, not the sentence**: `labelKey: 'STATUS.PASSED'`. That is why
  `STATUS` and `CHAT.suggestions` carry keys.
- The QA picks the language in Settings → Appearance. `useLanguage` swaps it in place: the window
  never reloads.
- Test names, comments, code and commit messages stay in English. Only the user-facing copy is
  translated.
